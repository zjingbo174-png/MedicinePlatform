# docs/02-design 设计基线（实验二）

本目录是《智慧医疗在线问诊与处方流转平台》实验二的系统设计交付物，对应实验报告第 2 章「设计规格说明书」。

| 文件 | 说明 |
|---|---|
| `设计规格说明书.md` | 设计规格说明书正文：概述、总体设计（架构决策 / 包图 / 部署图 / 鲁棒图 / 顺序图 / 设计类清单 / 活动图）、数据库设计（10 张表的详细清单与索引） |
| `../diagrams/design/` | 24 张图的 PlantUML 源文件（`.puml`）与渲染结果（`.png`） |

## 如何阅读与导出

1. 直接打开 `设计规格说明书.md`，正文已嵌入 PNG，Markdown 阅读器或 GitHub 均可预览；
2. 修改图时先改 `docs/diagrams/design/*.puml`，再用 PlantUML 重新导出 PNG：

```bash
java -jar plantuml.jar -charset UTF-8 -tpng docs/diagrams/design/*.puml
```

3. 实验报告定稿时，按正文图号、表号把图片与表格插入 Word 第 2 章。

## 设计基线约束

- **输入**：`docs/01-requirements/需求规格说明书.md` v1.0（2026-11-10 合并入 `main`）；
- **用例编号**：UC-01～UC-17，与需求文档一致；
- **处方状态**：DRAFT / PENDING_REVIEW / REJECTED / PENDING_DISPENSING / DISPENSED / CANCELLED，共 6 状态 9 迁移；
- **表数量**：10 张，按 S0～S4 增量创建；
- **架构**：模块化单体 + 前后端分离 + DDD 限界上下文，单库本地事务，不引入 MQ / 注册中心。

## 评审要点

1. 用例编号、状态编码、表名是否与需求基线一致；
2. 每个用例是否有明确的边界类 / 控制类 / 实体类，是否出现跨层调用；
3. 处方 9 条迁移是否都有实现方法与更新条件；
4. 表字段、索引是否覆盖需求中的查询场景；
5. 图 2-4～2-19 的鲁棒图与顺序图是否与表 2-1、2.2.2 的状态机约定一致。
